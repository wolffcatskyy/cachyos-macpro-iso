# MacPro6,1 beta build status (2026-09-25)

**UNTESTED BETA. Do not install or use this candidate ISO to replace macOS.** This branch is a proposed build pipeline and guarded installer adaptation, not an installable release. Do not merge without Michael's explicit word.

The latest official desktop ISO in the public index is 260809 (August 9); the public testing index had no ISO on September 25. This fork is a rolling `mkarchiso` profile, not a modification of the official ISO file. Its Mesa and KDE packages resolve against live repositories and are not pinned to 260809. The kernel source candidate is Linux 7.2.8; the five historical 7.0 patches have not been ported. The strict patch step must fail until they are ported, and a passing compile is not proof of Mac Pro support.

## Gates before anyone can install

1. Port all five CachyOS/BORE/BBR3/Mac Pro patches to 7.2.8. Resolve olddefconfig drift and verify firmware, Southern Islands AMDGPU, applesmc fan sysfs, Thunderbolt, Broadcom, EFI, KVM and CPU target on the built binary. The source package has no existing binary release. Its package currently emits `/usr/lib/modules/<release>/vmlinuz`, while this fork's GRUB entry and old ESP hook expect `/boot/vmlinuz-linux-macpro61`. Fix kernel-install/boot entry generation and verify on a real ESP. The old ESP hook is not copied to the installed target by this draft.
2. Inspect and test current CachyOS Calamares package paths/modules at runtime. This draft guards known upstream patterns and changes online pacstrap, hidden netinstall kernel group, and package list, but no real Calamares install has been completed. Ensure both live and installed `pacman.conf` see the same custom repository at the path used by pacstrap, then verify installed package names, versions, executable CPU baseline, bootloader entry and no stock kernels. Check Mesa and KDE/Plasma in the installed target, not only live manifest. Audit package upgrades so custom kernel is not replaced later.
3. Audit **every** live and installed executable for x86-64-v3/AVX2 leakage; `Architecture=x86_64` is not enough. Test a no-AVX2 VM and a real Ivy Bridge MacPro6,1. The Actions runner may have AVX2 and can hide an invalid binary. Check the custom kernel compiler target and patch compile flags.
4. Verify firmware-reported max fan RPM and actual tachometer speed from the beginning of live boot, through partitioning/install, and after installed boot. The live service asks for max every two seconds and fails loudly if sysfs is absent, but it is not tested on the hardware; users must never start a long install with fan control unverified. Confirm persistent fan service, SSH reachability from another device and UFW port 22 allow rule. Root password authentication in the live ISO should be reviewed before publishing.
5. CI is a privileged Arch container candidate, not a verified workflow. First run will expose package-name/dependency/mkarchiso/script mismatches; Actions artifact is **not** a signed release. No assumptions about free minutes, a six-hour completion, or caching until measured. Add automated VM install and manual physical Mac Pro acceptance before any release.

Performance candidate is documented in `PERFORMANCE.md`. No security mitigations are disabled. The `kernel/arch` source is copied from `wolffcatskyy/linux-mac` (September 23 tree), then changed as an untested candidate. The original repo remains separate; sync/ownership with it must be resolved rather than silently diverging.
